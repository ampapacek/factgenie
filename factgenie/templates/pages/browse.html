How Browse filters work
Basic behavior
  • Filters apply only to the currently selected dataset and split.
  • Match all keeps questions where all conditions are true. Match any keeps questions where at least one condition is true.
  • Each matched question appears once in navigation, even if several answers, annotators, spans, or sliders match.
  • Text matching is case-insensitive: top10, Top10, and TOP10 match the same text.
  • The main result count shows matched questions and the most specific matched evidence type. Span matches are counted as distinct span records, not as condition rows.
  • The smaller context line shows how many distinct answers and annotations contain matched evidence. Answers are counted per question and answer source. Annotations are counted per question, answer source, and annotator submission.
  • The matched-occurrence list is clickable. Click an occurrence to reveal the relevant answer or annotator, scroll to the match, and briefly pulse the exact target.
  • Use the expand button in the matched-occurrence panel when you want a taller list.
  • In Match any, counts are based on whichever conditions matched, so a matched question can come from question text, answer text, spans, sliders, or annotation metadata. Occurrence rows show the condition or conditions that caused each occurrence to match.
  • In Match all, rows stay compact because each listed occurrence already satisfies the whole filter.
  • While filters are active, navigation moves through matched questions. The navigation bar shows the matched-question position separately from the original question number.
  • After you apply filters, the browser URL includes the applied filter state and current question so the view can be shared or reopened.
  • Editing filters keeps the last applied results visible and marks them as Unsaved filter changes until you apply or reset.
  • Applying a filter with no results shows No matched questions, clears matched-occurrence highlights, and returns navigation to all questions.
Question and source data
  • Question searches only the text under Otázka when that section is detected. Otherwise it falls back to the whole example text.
  • Source data searches the Nalezené relevantní dokumenty section and is shown only when that section is detected for the selected dataset and split.
Span conditions
  • Span conditions have a Span group. Conditions in the same group must match the same span.
  • Choose New group when a span condition may be satisfied by a different span in the same annotation.
  • When multiple span groups match, the span count is the distinct union of all matched spans across those groups. If the same span satisfies more than one group, it is counted once.
  • For example, Span category is Chybí in Group 1 and Span reason regex \bNotInTop10\b in Group 1 means: keep questions where there is a Chybí span whose own reason matches NotInTop10.
  • Span category is Chybí in Group 1 and Span category is Nesrozumitelné in Group 2 means: keep questions with an annotation that contains both categories, possibly on different spans.
  • The matching span, reason text, answer text, or slider row is highlighted when possible. You can turn this off with Hide highlights and turn it back on with Show highlights.
Example: NotInTop10 and InSeafile on the same span

To find one span whose reason contains both NotInTop10 and InSeafile, use Match all and add two conditions:

  1. Span reason matches regex \bNotInTop10\b
  2. Span reason matches regex \bInSeafile\b

Prefer regex here because contains InSeafile also matches NotInSeafile. The \b parts are word boundaries, so \bInSeafile\b matches the standalone label InSeafile but not NotInSeafile.

Annotator names
  • If campaign pseudonymization is enabled, public users see and filter by city aliases only.
  • If pseudonymization is disabled, public users can show/hide and filter by both real annotator names and city aliases.
  • Authenticated users can see both real names and aliases.
