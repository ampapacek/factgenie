How Browse filters work
Basic behavior
  • Filters apply only to the currently selected dataset and split.
  • Match all keeps examples where all conditions are true. Match any keeps examples where at least one condition is true.
  • Each matching question appears once in navigation, even if several outputs, annotators, spans, or sliders match.
  • Text matching is case-insensitive: top10, Top10, and TOP10 match the same text.
Span conditions
  • With Match all, span conditions are evaluated on the same span. For example, Span category is Chybí and Span reason regex \bNotInTop10\b means: keep rows where there is a Chybí span whose own reason matches NotInTop10.
  • Multiple span-reason conditions also mean the same span must satisfy all of them.
  • The matching span, reason text, output text, or slider row is highlighted when possible. You can turn this off with Disable highlights.
Example: NotInTop10 and InSeafile on the same span

To find one span whose reason contains both NotInTop10 and InSeafile, use Match all and add two conditions:

  1. Span reason matches regex \bNotInTop10\b
  2. Span reason matches regex \bInSeafile\b

Prefer regex here because contains InSeafile also matches NotInSeafile. The \b parts are word boundaries, so \bInSeafile\b matches the standalone label InSeafile but not NotInSeafile.

Annotator names
  • If campaign pseudonymization is enabled, public users see and filter by city aliases only.
  • If pseudonymization is disabled, public users can show/hide and filter by both real annotator names and city aliases.
  • Authenticated users can see both real names and aliases.
