How to manage the campaign and redo workflow

Use the Page link to share the annotation URL with annotators, for example through your crowdsourcing platform.

Use the Download annotations button to export the campaign outputs collected so far.

For the full crowdsourcing basics, see the crowdsourcing annotation tutorial .

Redo annotations in this version

Redo is a per-annotator queue. There is no separate on/off toggle in the UI: as soon as an annotator has pending redo items, the normal annotation link serves those redo items first.

Redo saves do not delete the original submission. Each save archives the old active JSONL record and writes the corrected version as the new active annotation.

How to set up redo for an annotator
  1. Click the Expand button on the right side next to the Redo annotations title.
  2. Scroll to the Redo annotations section.
  3. You can select the annotator in the dropdown so the table only shows that annotator's examples.
  4. Use the condition builder if you want to target examples by annotation content, question/output text, free-text fields, or slider values.
  5. Select the rows you want to send back for correction.
  6. Add an optional shared instruction if you want the annotator to see a short note while reviewing the redo item.
  7. Use Add selected examples for a few individual items, or Add selected batches when you want the whole batch to go back to the same annotator.
Details of admin controls and filtering method
  • Add condition adds a filter row. Use Match all for AND behavior or Match any for OR behavior.
  • Span conditions are matched against the same saved span when Match all is selected. For example, Span category is Chybí plus Span reason does not contain top10 keeps rows with a Chybí span whose own reason lacks top10.
  • The same applies to regex filters: Span category is Chybí plus Span reason matches regex top10 means keep rows where there is a Chybí span whose own reason matches the regex.
  • Text filters can search the question, output, span reason, span text, or all saved text/reason fields. Regex filters use Python regular expressions without wrapping slashes.
  • Slider filters match saved slider labels and numeric values.
  • Allow skipped makes skipped examples selectable for redo. Skipped rows stay visible when it is off, but they cannot be selected.
  • Allow completed redo makes redo items that have already been saved once selectable for another correction pass. Completed rows stay visible when it is off, but they cannot be selected.
  • Select visible and Clear visible work only on the rows currently shown after filtering by annotator and span content.
  • Cancel selected pending items removes only pending redo items from the queue. It does not touch saved redo items or archived revisions.
  • Restore original annotation takes a completed redo item, archives the current active redo save, and restores the first archived original annotation as the active one again.
Queue and revision downloads
  • Queue JSON and Queue CSV download the current redo queue, including pending, completed, cancelled, reopened, and restored item status.
  • Revisions JSON and Revisions CSV download the archived annotation records created by redo saves and restore actions.
  • The queue is useful for seeing what was assigned for redo. The revisions are useful for auditing what active annotation was replaced and when.
What the annotator sees
  • The annotator opens the usual campaign link or login flow. No special redo URL is needed.
  • If the annotator has pending redo items, those items appear before normal free work.
  • The redo page uses Save current item so each corrected annotation is saved one item at a time.
  • Completed redo items are hidden by default, but they can be shown again for review when needed.
